# Lannacom AI Hub — ระบบที่เก่งขึ้นจากการใช้งาน

โมเดล AI ไม่ได้เรียนรู้จากแชท สิ่งที่ทำให้ระบบเก่งขึ้นคือความรู้และวิธีทำงานที่ดีที่เราสะสมไว้รอบโมเดล
แล้วป้อนกลับให้ AI ใช้ทุกครั้ง ไฟล์ในโฟลเดอร์นี้เป็นต้นฉบับของส่วนนั้น (แก้ที่นี่ก่อน แล้วค่อยนำไปใส่ในระบบ)

| ชั้น | อะไร | ไฟล์ / ที่อยู่ในระบบ |
|---|---|---|
| 1. บริบทขององค์กร | system prompt ที่ทุกโมเดลได้รับทุกแชท | `system-prompt.md` → `librechat.yaml` (`promptPrefix` ของทุก model spec) |
| 2. Memory ส่วนตัว | AI จำหน้าที่ งานที่ทำบ่อย และสไตล์ของแต่ละคน (เห็นเฉพาะเจ้าของ) | เปิดใน `librechat.yaml` (`memory`) แล้ว |
| 3. Agent เฉพาะงาน | ผู้ช่วยที่มีคำสั่งละเอียดสำหรับงานหนึ่งอย่าง | `agents/*.md` → สร้างใน LibreChat แล้ว share |
| 4. คลัง prompt | วิธีถามที่ได้ผลดี เรียกด้วย `/คำสั่ง` | `prompts.md` → Prompts ใน LibreChat แล้ว share |
| 5. วงจรปรับปรุง | feedback จากผู้ใช้ → ทีมดูแลปรับชั้น 1, 3, 4 ทุกเดือน | ด้านล่าง |

## ใส่ system prompt (ชั้น 1)

บน server (สคริปต์สำรองไฟล์เดิมให้ และรันซ้ำได้ จะแทนที่ prompt เดิม ไม่ซ้อน):

```bash
cd /opt/librechat/<ชื่อ> && python3 assistant/apply-system-prompt.py librechat.yaml
sudo docker compose -f docker-compose.yml -f docker-compose.override.yml -f docker-compose.<ลูกค้า>.yml up -d --force-recreate api
```

prompt ถูกส่งทุกข้อความ ยิ่งยาวยิ่งเพิ่มค่าใช้จ่ายเล็กน้อย จึงควรสั้นและคมที่สุด รายละเอียดเฉพาะงานไปไว้ใน Agent แทน

## หลักการแชร์ความรู้ข้ามผู้ใช้

งานขององค์กรเป็นข้อมูลอ่อนไหว (ข้อมูลภายใน, ทรัพย์สินทางปัญญา, ข้อมูลส่วนบุคคล — PDPA)

- **แชร์ "วิธีทำงาน" ไม่แชร์ "เนื้อหางาน"** — prompt, ขั้นตอน, checklist แชร์ได้; ข้อมูลและผลงานของใครของมัน
- **แชร์ด้วยความสมัครใจเท่านั้น** — เจ้าของกด Share เอง ระบบไม่ดึงจากแชทของใครไปใช้กับคนอื่นโดยอัตโนมัติ
- **มีคนคัดกรอง** — ทุกอย่างที่เข้าคลังกลางหรือ Agent ผ่านทีมดูแลก่อน
- **ผู้ให้บริการโมเดล** — ตั้งค่า OpenRouter (Settings → Privacy) ไม่ให้ใช้ผู้ให้บริการที่เก็บหรือนำข้อมูลไปฝึกโมเดล

## วงจรปรับปรุงรายเดือน (ชั้น 5)

ทีมดูแล 1–2 คน (แนะนำ: ตัวแทนฝ่ายที่ใช้งานมากที่สุด + ผู้ดูแลระบบ) ใช้เวลาประมาณ 1–2 ชั่วโมงต่อเดือน:

1. **เก็บ feedback** — ผู้ใช้กด 👍/👎 ใต้คำตอบ (และเขียนเหตุผลได้) ทีมดูสรุปจำนวนและเหตุผลรายเดือน
2. **รวบรวม prompt ที่ผู้ใช้แชร์** — ลองใช้ ปรับให้ใช้ได้กว้างขึ้น แล้วรวมเข้า `prompts.md` และคลังกลาง
3. **ปรับ Agent / system prompt** — จากปัญหาที่เจอซ้ำ เช่น AI ใช้ภาษาพูดในบทความ → เพิ่มกฎใน Agent;
   บันทึกในตาราง "บันทึกการปรับปรุง" ของไฟล์ Agent ว่าเปลี่ยนอะไร เพราะอะไร
4. **ทดสอบก่อนใช้จริง** — ลองกับงานตัวอย่าง 3–5 งาน เทียบกับของเดิม แล้วค่อยอัปเดตในระบบ
5. **แจ้งผู้ใช้** — สรุปสั้นๆ ว่าเดือนนี้มีอะไรใหม่ (Agent, prompt) ให้คนใช้ต่อยอด

## สิ่งที่ยังต้องทำ

- ยืนยันนโยบายข้อมูลกับองค์กร (ข้อมูลแบบไหนห้ามใส่ระบบ)
- กำหนดทีมดูแลและรอบประชุม
- ฐานความรู้ขององค์กร (ระเบียบ, คู่มือ, แบบฟอร์ม) ใส่เป็นไฟล์ให้ Agent ค้น — รอเอกสารจากองค์กร
- Agent ตัวถัดไป ตามงานที่ใช้บ่อยจริง (ดูจาก feedback เดือนแรก)
